# P1 · 硬件急停 / 看门狗板 / E-Stop & Watchdog Board

把 `safety_state_machine` 的 **Emergency 分支做成硅级 fail-safe**：即使 香橙派 死机、MCU 固件跑飞、或控制线程饿死，也能在**硬件层面**切断舵机动力并回中。软件安全判据不可用时，这是最后一道防线。

> 状态：设计文档。BOM 见 [`bom.md`](bom.md)。可与 P0 板合板，或作为独立小板靠近电源/舵机放置。

## 1. 为什么必须硬件化

- 软件 `Emergency` 依赖 Linux 进程存活与线程调度；内核卡死/看门狗未触发时失效。
- 主动悬架是**载人与运动机构**，失控代价高。硬件急停必须满足：不依赖任何软件即可动作。

## 2. 两大功能

### 2.1 心跳看门狗（看门狗 MCU/比较器）

- P0 板 MCU 周期输出心跳（翻转 GPIO 或喂外部看门狗 TPS3823/MAX6814）。
- 香橙派另发**软件心跳**到 P0 板；超时（对应 `link_lost_timeout_s = 0.5 s`）→ P0 板立即进入 Emergency，拉急停。
- 外部看门狗超时 → 复位 MCU（而非只告警）。

### 2.2 硬件急停断电

- 急停 MOSFET（高边，位于舵机电源轨）由**多源 OR** 控制：
  - 独立急停按钮（直连栅极，机械优先）；
  - P0 板 MCU 急停信号；
  - 外部看门狗超时信号。
- 任一源有效 → 切断舵机电源，作动器自然回中/失电（需确认舵机失电行为安全）。
- 复位需显式操作（对应 `safety_state_machine` 的"需显式复位"语义）。

## 3. 设计要点

- **Fail-safe 默认态**：失电即急停（MOSFET 默认关断），避免"断线反而使能"。
- **去抖与锁存**：急停按钮信号硬件去抖 + 锁存，防止误触恢复；恢复走独立复位通道。
- **冗余**：硬件急停与软件 `Emergency` 并存，不互相替代。
- **指示**：急停状态 LED + 触点反馈（可选上报 MCU/香橙派）。

## 4. 与 P0 / 电源板配合

- 本板可置于电源板输出与舵机之间（物理切断动力），由 P0 板与急停钮共同驱动栅极。
- 信号链：`急停钮 / 看门狗 / MCU` → OR 逻辑 → MOSFET 栅极。
